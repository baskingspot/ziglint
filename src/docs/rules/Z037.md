# Z037: Unused container declarations

Reports a container-scoped `const`, `var`, or `fn` declaration whose name has no
reference in the file. Top-level declarations and members of named containers
are checked. The Zig compiler already checks locals inside function bodies.

Public declarations, exported declarations, and declarations inside test blocks
are excluded. Z013 continues to report unused imports. References through
`Type.member` and inferred `.member` syntax count.

## Examples

### Bad

```zig
// expect: Z037
const unused = 42;
// expect: Z037
var counter: u32 = 0;
// expect: Z037
fn helper() void {}

pub fn main() void {}
```

### Good

Reference each declaration:

```zig
const answer = 42;
var calls: u32 = 0;

fn helper() void {
    calls += 1;
}

pub fn main() void {
    _ = answer;
    helper();
}
```

Public and exported declarations remain available to other code:

```zig
pub const visible = 42;
export fn entry() void {}
```

A direct `@export` argument counts as a reference:

```zig
fn entry() void {}

comptime {
    @export(entry, .{ .name = "entry" });
}
```

Declarations inside test blocks are excluded:

```zig
test "example" {
    const local = 42;
    _ = local;
}
```

## Limitations

Name matching is file-wide. A reference to an equal name in another container
can hide an unused declaration.

Reflection can hide references. The check cannot see a name constructed by
`@field`, declaration iteration through `@typeInfo`, or an `@export` call that
does not name the declaration as an identifier.

## Rationale

The compiler cannot reject an unused container declaration because another
module can reference a public one. Private declarations with no references are
dead code. Removing them keeps the container's API and implementation clear.
